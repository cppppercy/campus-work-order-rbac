# 《系统设计与分析》第三次作业报告

## 题目

基于事件监听机制的 RBAC 校园工单权限管理系统

## 摘要

本项目设计并实现了一个 Java Swing 桌面管理系统，将校园设施工单作为业务场景，将用户、角色、权限和动态授权作为独立可复用模块。系统使用 ActionListener 响应用户操作，使用 SwingWorker 执行数据库工作；所有授权关系存储于 SQLite，并在每次 Service 调用时重新查询。实现结果能够演示不同账号的菜单差异、同一页面的按钮差异、管理员动态授权、越权拒绝、数据持久化和审计。

## 需求与设计决策

核心目标是证明权限来自数据库且不能绕过。为此系统采用分层架构：UI 负责呈现，Service 负责业务边界，统一 Access 负责可信身份与权限，Repository 负责参数化 SQL，Database 负责事务。UI 权限快照只决定显示；Service 授权查询才是安全判断。

桌面应用没有服务器端令牌，因此设计了进程内随机会话注册表。登录成功签发随机令牌，业务参数不能指定操作人。多角色权限以 SQL 查询并集获得，未授权默认拒绝。写操作把权限检查、数据修改和成功审计放入同一 SQLite 事务；拒绝审计在回滚后独立写入。

## 功能实现

系统提供登录、工作台、工单、用户、角色权限、统计和审计页面。工单支持 CRUD、分派、状态流转、筛选与 CSV 导出。管理员可创建和维护用户、分配多个角色、创建角色并以复选框调整权限。角色授权修改后，刷新界面即可更新按钮；服务层从数据库读取新授权，因此撤权不依赖重新登录。

数据库包含 users、roles、permissions、user_roles、role_permissions、work_orders 和 audit_logs 七张业务表，以及 schema_version。外键、唯一约束、检查约束和索引维持一致性。首次初始化在事务中执行，版本存在后不会重复插入或恢复被撤销的权限。

系统保护最后一个有效管理员。判断依据是启用用户的实际权限并集，而非角色名；所有可能破坏管理能力的变更都在事务末尾检查，不满足则回滚。

## 事件监听机制

按钮和菜单显式绑定 ActionListener。监听器先在 EDT 读取输入并形成不可变参数，再由 BackgroundAction 启动 SwingWorker。`doInBackground` 调用 Service，`done` 在 EDT 更新表格、状态栏或错误提示。回调同时检查会话令牌和页面修订号，避免用户退出或换页后旧任务修改新界面。

## 权限控制分析

系统区分菜单、页面和动作权限。菜单控制入口可见性，页面权限控制导航，动作权限控制按钮与服务。前三者改善体验，真正安全边界是 Service。RBAC0 已完整实现；RBAC1 角色继承、RBAC2 约束及二者结合的 RBAC3 作为扩展分析，详见 `RBAC_ANALYSIS.md`。

## 测试与结果

自动化测试使用真实临时 SQLite，不模拟权限布尔值。默认构建覆盖初始化、密码、约束、事务、登录、四角色、动态授权与撤权、多角色并集、重启持久化、越权调用、最后管理员、审计、工单完整生命周期、CSV 安全和 SwingWorker 线程。图形 profile 在真实窗口中登录 admin 与 viewer，验证导航和同页按钮差异并生成截图。

实际命令、数量和环境记录在 `TEST_REPORT.md`。报告只记录本机真正执行的结果。

## 结论与限制

项目满足课程核心目标：能运行、能交互、权限来自数据库、能动态修改、能证明服务层拒绝越权，并能解释事件监听和 RBAC 原理。当前范围是单机 RBAC0，不实现角色继承、职责分离、组织数据范围或网络多用户并发；拥有本地数据库文件写权限的人仍可绕过应用直接修改文件，这属于操作系统和部署边界。
